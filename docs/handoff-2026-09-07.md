## The one thing to fix first: the Chrome pool dies mid-run

In `.wowlidator/reports/catalogs/ec-full-run-luna-resume9.log` (14,867 lines):

- Line **7003** is the first `browserContext.newCDPSession: Target page, context
  or browser has been closed`. 22 cases died this way.
- Line **13889** is the first `browserType.connectOverCDP: connect ECONNREFUSED`.
  By then the pool was gone; 45 more cases could not start at all.
- Every port died — 9333 through 9340 — 4 to 16 failures each.
- No `Out of memory`, `SIGKILL`, `Target crashed` or renderer-crash text
  anywhere in the log. Whatever kills them is quiet.

**It is not the new case ceiling.** The first browser death (line 7003) is well
before the first ceiling cut (line 8139).

Leads worth pulling, in the order I would try them:

1. The run used `--stop-chrome`. Check `chromeStartedByUs` and the stop path in
   `src/cli/artifacts.ts` — does anything stop a *pooled* Chrome before the
   suite ends, e.g. on a persona hand-off or when a lane is recycled?
2. `src/browser/pool.ts` — does a lane that loses its browser take that pool
   member out of rotation, or keep handing the dead one out? The ECONNREFUSED
   spread across every port suggests cases kept being routed to dead ports.
3. The abort path added in `be285d6` is a known, accepted limitation (below) and
   is *not* the trigger here, but it could compound once browsers are already
   unhealthy. Rule it in or out with a short catalog and a small ceiling.

Cheap repro: run a 20–30 case slice with `--browsers 8` and watch
`pgrep -f "remote-debugging-port=93" | wc -l` over time. It should stay at 8.

## Providers

`wowlidator doctor` is the only way to know a model id still resolves; the ids
drift faster than the code.

- **codex-cli `gpt-5.6-luna`** — what the last two runs used. No quota wall in
  ~14 hours. `codex exec failed: Reading prompt from stdin…` appears at roughly
  3% of calls (530 times in one run); each one degrades a single step (a skipped
  risk judgement or diagnosis), never a verdict. The roll-up now prints the
  per-role tally. Note `codex exec resume` does **not** inherit `-m`, so pass the
  model explicitly or it defaults to an id this CLI cannot use.
- **agy-cli (Gemini)** — do not use for a full catalog. Its quota allows roughly
  18 minutes of 8-lane work per 5 hours; it poisoned 191 cases across two
  attempts on 2026-09-05/06.
- **claude-\*** — works; the suite-wide quota hold pauses at
  `WOWLIDATOR_QUOTA_HOLD_PERCENT` (default 85%) so a spent window never
  "finishes" the catalog on refusals.

Known limits of `be285d6`, both real and both seen live:

- A case that is re-run (the interference solo re-run) gets a **fresh** 20
  minutes, so one case still reached ~55 minutes of wall clock.
- The abort does not cancel the in-flight `executeFlow`; it stops awaiting it.
  The returned bundle is `structuredClone`d so the report is not mutated
  afterwards, but the orphan keeps driving the page until `runner.close()` lands.

## Smaller things noticed and not fixed

- The mutation gate reads control **names**, so clicking a tab named
  `สร้างเอกสาร` ("create document") is read as a write and takes a data lock
  early. Harmless to correctness; costs parallelism.
- A case whose workflow goal mentions delete/terminate takes the **global** lock
  from its first leg, before it has found anything to delete. One case held it
  15 minutes across 11 legs while 7 lanes waited. The same defer-to-first-write
  fix that landed for unknown-place windows would apply.
- A dependent is sealed `blocked` the moment the ledger says its parent never
  ran, even when the parent is about to be authored in the same pass. It should
  wait instead.
- Disk fills fast: `~/.codex` reached 5.3 GB and the report media folders are
  ~500 MB per run. One overnight run filled the volume and killed a scheduled
  relaunch.
